# 简历投递 Agent 需求规格草案

更新时间：2026-08-04

## 1. 项目定位

本项目是一个面向 AI 应用开发实习投递的本地网页 Agent，使用 Python 作为主要开发语言。它应帮助用户分析岗位 JD、判断岗位是否值得投递、生成定制化沟通内容、跟踪投递进度，并在收到面试邀请后主动生成面试准备材料。

第一阶段不追求完全自动投递，而是先做成“本地求职驾驶舱”：信息本地保存、分析结果可解释、投递动作可确认。后续再逐步接入浏览器自动化。

## 2. 用户画像与目标岗位

用户当前为智能科学与技术本科在读，目标方向包括：

- AI 应用开发实习
- Agent 开发实习
- AI 后端 / 大模型应用后端实习

暂不主攻：

- 纯算法实习
- 前端或全栈主导岗位
- 与 AI 应用开发无关的运营、销售、标注、培训类岗位

用户当前简历形式为 Word 文档，后续可能转为 PDF。

真实简历文件路径应由本地配置维护，不提交到开源仓库。

## 3. 已确定偏好

### 3.1 投递平台

用户已有账号或接受使用的平台包括：

- Boss 直聘
- 猎聘
- 实习僧
- 智联招聘
- 前程无忧
- 其他可用平台、公司官网、邮箱投递也可接受

### 3.2 地点与工作方式

可接受城市：

- 北京
- 上海
- 广州
- 深圳
- 杭州
- 重庆
- 成都
- 南方大部分地区

可接受形式：

- 线下实习
- 远程实习
- 混合办公

实习时间：

- 每周约 5 天
- 实习周期 3 个月及以上

### 3.3 薪资偏好

薪资应设计为可配置项，不写死。

建议默认值：

- 薪资底线：150 元/天
- 合理目标：200-350 元/天
- 优质目标：300-500 元/天

如果岗位成长性、导师质量、公司质量非常好，可允许用户手动豁免薪资底线。

### 3.4 投递策略

默认策略：

- 高匹配：必投
- 中匹配：可冲
- 低匹配：跳过

每日投递数量应可配置，例如：

- 保守：5-10 个/天
- 标准：10-20 个/天
- 积极：20-30 个/天
- 自定义数量

### 3.5 沟通风格

生成的打招呼、私信、邮件和求职信应混合：

- 礼貌正式
- 学生真诚型

避免过度营销、夸大能力、伪造经验。

### 3.6 V0.1 已确认产品决策

- 第一版不做账号登录，默认本机单用户使用。
- 第一版提供本地网页界面。
- 第一版界面包含：仪表盘、JD 分析、岗位列表、面试准备。
- 简历解析后，用户可以在网页里手动编辑候选人画像。
- 支持多份简历管理，例如 AI 应用开发版、Agent 开发版、AI 后端版。
- JD 导入第一版只支持粘贴文本，不做 CSV/Excel 批量导入。
- JD 分析和内容生成使用 OpenAI-compatible API，具体模型和服务地址可配置。
- OpenAI-compatible API 不内置默认服务商，由用户自行配置。
- API Key 允许保存在本地 `.env` 文件中，也应支持环境变量读取。
- GitHub 仓库信息支持手动刷新具体仓库的 README、语言和最近提交，用于候选人项目事实库；不自动扫描整个账号。
- 公司风险判断第一版允许联网搜索公开信息。
- 多份简历默认包含：AI 应用开发版、Agent 开发版、AI 后端版、通用版。
- 支持黑名单公司和黑名单关键词。
- 面试准备支持 3 天冲刺、7 天准备等按天学习计划。
- 支持记录每次面试反馈，并反向优化后续模拟面试。
- 不需要导出投递周报；面试复盘需要支持保存，并可导出 Markdown 或 PDF。
- V0.1 支持粘贴面试转写文本做复盘，V0.2 再支持上传录音并本地 ASR 转写；两种入口后续都保留。
- V0.1 支持生成话术后一键复制到剪贴板。
- 每个跳过的岗位需要保存“为什么没投”的原因。
- 多份简历第一版先只登记四个版本名称和文件路径，不自动复制生成文件。
- 公司搜索结果页面需要展示原始来源链接。
- JD 分析失败时，允许保存原始 JD 为“待分析”，之后重试。
- 支持多个 OpenAI-compatible 模型配置档，并可按任务选择不同模型以控制成本。
- 公司联网搜索默认自动分档，也允许用户手动选择搜索深度。
- 面试复盘 Markdown 导出不需要固定模板，优先按当次面试内容生成结构化复盘。
- V0.1 采用推荐的 `.env` 配置方案：支持读取 `.env` 和系统环境变量；如果没有 `.env`，应用提供模板和引导。
- V0.1 设置页允许直接填写 API Key；保存时写入本地 `.env` 并立即生效，页面只显示打码状态。
- 多模型路由的任务分配需要支持可视化编辑。
- 模型预算提醒以 token 消耗为主，并可结合模型单价估算费用。
- Token 消耗提醒默认不设置阈值，只展示统计；用户后续可自行添加提醒阈值。
- V0.2 引入本地 ASR 时，允许应用在用户确认后自动下载模型文件；模型下载一次后本地缓存复用。
- V0.1 候选人画像维护 GitHub 地址和项目演示地址。
- 本地单用户使用场景下，手机号、邮箱等个人信息在测试界面默认不打码；但仍不得写入日志或上传第三方。
- OpenAI-compatible API 配置值由后续可视化配置界面填写，不在需求文档中记录真实 Key。
- 首批 JD 测试样例见 `docs/sample_jds.md`。

## 4. 产品原则

### 4.1 本地优先

用户简历、岗位记录、沟通记录、面试记录默认保存在本地 SQLite 数据库中。除非用户明确配置，不上传到第三方服务。

### 4.2 人机协作

第一版所有高风险动作都需要用户确认，包括：

- 登录招聘平台
- 发送第一条消息
- 点击投递
- 上传简历
- 修改或发送包含个人信息的内容

后续可逐步加入自动化，但需要保留可审计日志和暂停开关。

### 4.3 不伪造与不越界

Agent 不应：

- 编造用户没有的技能、项目、学历或实习经历
- 绕过平台验证码、风控或付费限制
- 批量骚扰招聘方
- 投递明显不匹配或高风险岗位
- 存储招聘平台密码、短信验证码、Cookie、Token

### 4.4 可解释

每个岗位的判断必须说明原因，包括：

- 为什么适合
- 缺哪些技能
- 风险点是什么
- 建议投递话术如何突出用户优势

### 4.5 LLM 与自动投递边界

LLM 负责理解、判断、生成和规划，不直接具备操作招聘平台网页的能力。后续自动投递需要由浏览器自动化模块执行，例如 Playwright 打开网页、读取页面、填写输入框、点击按钮。

推荐边界：

- LLM 决定：岗位是否值得投、用哪份简历、怎么打招呼、下一步动作是什么。
- 浏览器自动化执行：打开页面、提取页面文本、填写表单、点击投递或发送。
- 用户确认：登录、验证码、敏感信息提交、首次自动投递策略放权。

因此，自动投递不是“只靠 LLM 自己完成”，而是 LLM + 浏览器自动化 + 本地状态管理 + 人机确认的组合。

## 5. 功能范围

自动化阶段的具体执行路线、沟通模式、审批边界、浏览器扩展方案、模型路由和面试状态机，见 `docs/agent_automation_plan.md`。本需求文档保留产品总目标和模块边界，后续自动化实现以路线文档为准。

### 5.1 V0.1：本地求职驾驶舱

V0.1 只做本地网页界面和分析辅助，不直接自动投递。

核心功能：

- 本机单用户使用，不做账号登录
- 导入、读取和管理多份用户简历
- 简历解析后支持手动编辑候选人画像
- 粘贴 JD 文本进行分析
- 手动录入岗位来源、链接、公司、城市、薪资
- 使用 OpenAI-compatible API 自动提取岗位职责、技术栈、硬性要求、加分项
- 联网搜索公司公开信息，辅助判断公司可信度和岗位风险
- 根据用户简历和偏好进行匹配评分
- 输出投递建议：必投、可冲、跳过
- 生成 Boss/猎聘/实习僧等平台的打招呼话术
- 生成邮箱投递正文
- 记录岗位状态
- 面试邀请后生成面试准备材料

### 5.2 V0.2：半自动浏览器辅助

V0.2 引入浏览器自动化，但仍由用户处理登录和验证码。

核心功能：

- 打开指定岗位链接
- 从页面提取 JD 文本
- 自动填入沟通话术
- 在用户确认后点击发送或投递
- 记录投递结果
- 捕获页面错误或失败原因

### 5.3 V0.3：受控自动投递

V0.3 在高置信度和低风险平台上做自动投递。

核心功能：

- 根据每日投递上限自动处理候选岗位
- 只自动投递高匹配且低风险岗位
- 中匹配岗位进入待确认队列
- 对高风险岗位自动跳过并说明原因
- 支持随时暂停
- 支持自动化行为日志回放

## 6. 核心模块

### 6.1 简历资料模块

输入：

- Word 简历
- PDF 简历
- 手动补充信息

需要抽取：

- 基本信息
- 教育经历
- 技能栈
- 项目经历
- 可证明成果
- GitHub / 作品链接
- 求职偏好

输出：

- 标准化候选人画像
- 可供 JD 匹配使用的技能标签
- 可供面试准备使用的项目事实库

多简历管理：

- 每份简历有独立名称、目标方向和文件路径。
- 每份简历可关联一份候选人画像，也可以继承通用画像后局部调整。
- 匹配岗位时，Agent 应推荐最适合该 JD 的简历版本。
- V0.1 支持用户手动切换简历版本；后续版本再做自动选择和自动定制。
- V0.1 默认登记四个简历版本名称：AI 应用开发版、Agent 开发版、AI 后端版、通用版。
- V0.1 不自动复制生成四份简历文件，用户后续自行补充或替换文件路径。

### 6.2 JD 分析模块

输入：

- 粘贴的 JD
- 岗位链接
- 平台名
- 手动补充字段

需要抽取：

- 岗位名称
- 公司名称
- 城市
- 薪资
- 每周实习天数
- 实习周期
- 职责描述
- 必备技能
- 加分技能
- 技术栈
- 学历/年级要求
- 语言/英语要求
- 是否有转正要求
- 潜在风险点

V0.1 使用 OpenAI-compatible API 做结构化抽取。模型输出必须经过基本校验，不能直接把不完整或格式错误的结果写入核心字段。

失败处理：

- JD 分析失败时，保留原始 JD 文本。
- 失败岗位保存为“待分析”状态。
- 记录失败原因，例如模型调用失败、结构化输出校验失败、联网搜索失败。
- 用户可以稍后重试分析。
- 如果只有联网搜索失败，JD 基础分析仍可保存，风险信息标记为待补充。

### 6.3 匹配评分模块

默认评分维度：

- 技术匹配：35 分
- 成长性：25 分
- 薪资匹配：15 分
- 地点与时间匹配：10 分
- 公司可信度与风险：15 分

默认结论：

- 80 分及以上：高匹配，建议必投
- 60-79 分：中匹配，建议可冲
- 60 分以下：低匹配，建议跳过

扣分项示例：

- 要求算法论文、模型训练、CUDA 等明显超出当前目标方向
- 要求全栈主导且前端占比很高
- 薪资低于底线且无明显成长性
- 公司信息不透明
- 岗位描述混乱或疑似培训/外包/销售

### 6.4 公司与岗位风险评估模块

默认高风险信号：

- 要求交钱、贷款、培训费、押金
- 以招聘名义引导购买课程
- 公司名称、办公地址、业务信息模糊
- 岗位标题写 AI，但职责主要是销售、客服、运营、标注
- 薪资异常高但要求极低
- 要求提供身份证照片、银行卡等非必要敏感信息
- 面试流程中要求下载不明软件或私下转账
- 命中用户维护的黑名单公司
- 命中用户维护的高风险关键词

默认谨慎信号：

- 0-20 人且未融资
- 无官网或公开产品
- JD 过短，技术要求不清楚
- 只写“会使用 ChatGPT”但没有工程内容
- 长期招聘大量实习生但缺少正式团队信息

风险处理：

- 高风险：默认跳过
- 谨慎：降权，并进入人工确认
- 低风险：正常评分

联网搜索：

- V0.1 允许根据公司名、岗位名、城市进行公开网页搜索。
- 应尽量覆盖公司官网、招聘平台公司页、公开工商信息、新闻/舆情、产品介绍等来源。
- 搜索结果只作为辅助证据，不能替代人工判断。
- 需要记录引用来源、搜索时间和简短摘要。
- 页面需要展示原始来源链接，便于用户自行复核。
- 如果联网失败，应降级为仅基于 JD 文本判断，不阻断 JD 分析。
- 搜索深度默认自动分档，也允许用户手动选择。
- 如果联网搜索由带搜索能力的 LLM 或 LLM 工具链完成，主要成本计入模型 token 统计。
- 如果后续接入独立搜索 API 或浏览器搜索适配器，应额外记录搜索请求次数、搜索方式和失败状态。

搜索深度分档：

- 快速搜索：只查公司名、岗位名和招聘平台公开信息，适合明显低匹配或只需粗筛的岗位。
- 标准搜索：查公司官网、招聘平台公司页、公开产品信息、基础工商/企业信息，适合大多数中高匹配岗位。
- 深度搜索：进一步查新闻、社交平台讨论、负面舆情、长期招聘情况、业务真实性，适合高匹配但公司信息不足或存在谨慎信号的岗位。

自动分档规则：

- 低匹配且无明显风险：快速搜索。
- 中匹配或高匹配：标准搜索。
- 高匹配但公司信息不足：深度搜索。
- 命中谨慎信号：深度搜索。
- 命中高风险信号：可直接跳过；如果用户要求复核，再执行深度搜索。

黑名单：

- 支持黑名单公司名。
- 支持黑名单关键词。
- 支持风险关键词分级，例如直接跳过、谨慎确认、仅提示。
- 默认黑名单关键词包括：培训费、贷款、押金、无薪、课程顾问、电话销售、邀约、拉新、地推、兼职推广、收费内推、包装简历。

### 6.5 投递内容生成模块

需要生成：

- 平台打招呼短句
- 稍长版私信
- 邮箱投递正文
- 简历定制建议
- 技能差距提醒
- 一键复制按钮

话术要求：

- 不夸大
- 不编造
- 突出 RAG、FastAPI、SQLite、评测、项目落地能力
- 根据 JD 自动调整重点
- 保留学生身份的真诚感

一键复制说明：

- 一键复制只把生成的话术复制到系统剪贴板。
- 一键复制不等于自动发送，不会触发平台投递或聊天发送。
- 用户仍然可以在招聘平台输入框中自行粘贴、检查和发送。
- 适用场景包括 Boss 直聘开场白、猎聘私信、实习僧沟通文本、邮箱正文草稿。

示例方向：

> 您好，我是智能科学与技术本科在读，正在寻找 AI 应用开发/大模型应用开发实习机会。近期做过一个本地优先的 AI 伴侣与 RAG 知识库项目，实践了 Python、FastAPI、SQLite、文档解析、检索评测和大模型 API 接入。看了贵岗位对 AI 应用落地和 Agent/RAG 方向的要求，感觉比较匹配，希望有机会进一步沟通。

- 待投递

- 已沟通

- 平台
- 链接
- 城市
- 薪资

- 风险等级

- 下一步动作

跳过原因：

- 低匹配跳过、高风险跳过、薪资不合适、城市/时间不合适、岗位方向不符、公司信息不足等原因需要保存。
- 跳过原因既可以由 Agent 自动生成，也可以由用户手动修改。
- 后续可基于跳过原因复盘投递策略。

### 6.7 面试准备模块

触发条件：

- 用户手动标记收到面试邀请
- 或后续从聊天记录中识别到面试邀请

需要生成：

- JD 技术点拆解
- 针对岗位的复习清单
- 3 天冲刺计划
- 7 天准备计划
- 用户项目可能被追问的问题
- RAG/Agent/Python/FastAPI/SQLite 相关题库
- 模拟面试对话
- 面试后复盘模板

题目类型：

- 项目经历深挖
- Python 基础
- FastAPI/后端基础
- RAG 流程与优化
- Prompt Engineering
- Agent 工具调用与工作流
- 数据库与检索
- 工程测试与部署
- 行为面试问题

面试反馈记录：

- 用户可以手动记录面试中没有回答上来的问题。
- 用户可以记录回答不满意、表达不清、被追问卡住的问题。
- 用户可以记录面试官关注的技术点、项目点和行为问题。
- Agent 应根据反馈更新后续模拟面试重点。
- Agent 应把高频薄弱点沉淀为复习清单。
- 当前第一版支持手动记录面试薄弱点，并在同岗位后续准备中带入“待练习”薄弱点；自动统计高频薄弱点可后续增强。

面试录音分析：

- 支持作为后续增强能力纳入规划。
- 推荐流程：上传本地录音文件 -> 本地 ASR 转写 -> 用户确认转写文本 -> LLM 做复盘分析。
- 默认不上传完整录音到第三方服务。
- V0.1 可先支持粘贴面试转写文本进行复盘。
- V0.2 或后续版本再接入本地开源语音识别工具，支持自动转写。
- 复盘输出包括：没答上来的问题、回答含糊的问题、可补强知识点、项目表达问题、下一轮模拟面试题。

## 7. 初始技术方案

建议技术栈：

- Python
- FastAPI
- SQLite
- SQLAlchemy 或 SQLModel
- Jinja2 或轻量前端页面
- Playwright 用于后续浏览器自动化
- python-docx / pypdf 用于简历解析
- OpenAI-compatible API 用于 JD 结构化分析、匹配解释、投递话术和面试准备
- 可选：本地 embedding 或 OpenAI-compatible embedding 用于语义匹配
- 可选：联网搜索模块用于公司公开信息检索
- 可选：本地开源 ASR 用于面试录音转写

V0.1 可以先不用复杂前端框架，降低实现成本。

模型配置建议：

- 支持配置 `base_url`
- 支持配置 `api_key`
- 支持配置 `model`
- 支持配置 `temperature`
- 不内置默认服务商。
- API Key 可保存在本地 `.env` 文件或环境变量中。
- API Key 不写入日志和导出文件。
- 支持多个配置档，例如 DeepSeek、OpenAI-compatible、本地转发、备用模型。
- 支持按任务配置模型，用于节省开支和控制质量。

模型路由建议：

- 低成本模型：JD 初步结构化抽取、关键词提取、普通话术初稿、状态摘要。
- 中等模型：岗位匹配解释、简历版本推荐、公司搜索结果摘要、跳过原因生成。
- 高能力模型：复杂 JD 判断、面试深挖题、面试复盘、项目追问、关键投递文案终稿。
- 失败兜底：如果任务模型调用失败，可切换到同组备用模型，或保存任务为待重试。
- 成本控制：每类任务可配置最大输入长度、最大输出长度、temperature 和是否允许调用高能力模型。

`.env` 配置方式说明：

- 手动创建 `.env`：用户自己创建文件并填入 API Key，透明度高，不容易把 Key 误写进应用数据库，但对新手不够友好。
- 应用引导创建 `.env`：应用检测到没有配置时，提供模板和说明，帮助用户生成本地 `.env` 文件；设置页也可以直接填写 Key 并写入本地 `.env`，使用方便，但实现时必须避免把 Key 打印到日志或页面历史。
- 环境变量：把 Key 配到系统环境变量里，适合长期使用和更安全的部署，但 Windows 上设置和排查稍麻烦。
- 推荐折中：V0.1 支持读取环境变量和 `.env`；如果 `.env` 不存在，应用提供模板和引导，不强制在网页表单里保存密钥。

模型路由可视化编辑：

- 页面展示任务类型、当前模型配置档、备用模型、最大输入长度、最大输出长度、temperature。
- 用户可以为不同任务选择不同模型，例如 JD 抽取用低成本模型，面试复盘用高能力模型。
- 支持恢复默认路由。
- 支持临时为单次任务切换模型。

Token 消耗提醒：

- 记录每次模型调用的任务类型、模型配置档、输入 token、输出 token、总 token、调用时间和成功/失败状态。
- 如果模型返回 usage 字段，优先使用真实 usage。
- 如果模型不返回 usage 字段，可用本地估算作为近似值，并在界面标注为估算。
- 支持按日、周、月统计 token 消耗。
- 默认不设置提醒阈值，只展示统计。
- 后续可支持用户自行配置提醒阈值，例如每日总 token、强模型 token、预计费用。
- 如果用户维护模型单价，可估算费用；没有单价时只展示 token 消耗。

本地 ASR 候选方案：

- Whisper：通用开源语音识别模型，生态成熟。
- faster-whisper：基于 CTranslate2 的 Whisper 高性能实现。
- whisper.cpp：适合本地 CPU/GPU 轻量部署。
- FunASR：中文场景可重点评估的开源语音识别工具包。

ASR 选型原则：

- 优先本地运行。
- 优先中文识别效果和 Windows 可用性。
- 模型文件下载、推理速度和硬件占用应可解释。
- 如果本地 ASR 不可用，允许用户粘贴转写文本继续复盘。
- ASR 模型正常只需要下载一次到本地缓存，后续复用本地模型文件。
- 只有切换模型、升级模型版本、清理缓存或缓存损坏时，才需要重新下载。
- 模型下载应显示模型名称、大小、保存路径和预计耗时。
- V0.2 允许应用在用户确认后自动下载模型文件。
- 应提供手动下载/导入的备选路径。

当前机器初步适配建议：

- 已知配置：AMD Ryzen 7 8845HS，8 核 16 线程；约 32GB 内存；AMD Radeon 780M 核显；Windows 11；未检测到 NVIDIA/CUDA。
- 优先路线：V0.2 先评估 FunASR 或 faster-whisper 的 CPU/轻量本地方案。
- 中文面试复盘优先：优先评估 FunASR，重点看中文准确率、标点、长音频切分和 Windows 安装复杂度。
- 通用兼容优先：保留 faster-whisper 作为备选，优先使用 small 或 medium 模型的 CPU int8 推理。
- 极简本地部署备选：whisper.cpp 可作为轻量方案，适合后续做离线、低依赖测试。
- 不建议第一优先：原版 Whisper，主要因为 PyTorch/ffmpeg/模型依赖更重，CPU 路线下速度可能不如专门优化实现。
- 音频处理依赖：当前未检测到 `ffmpeg`，后续做录音自动转写时需要作为依赖检查或内置安装指引。

界面结构：

- 仪表盘：展示今日待处理、已投递、面试中、高风险提醒。
- JD 分析：粘贴 JD，选择简历版本，运行分析，查看评分和建议。
- 岗位列表：管理岗位状态、筛选匹配等级、查看沟通记录。
- 面试准备：基于岗位和简历生成复习计划、题库和模拟面试。

## 9. 非功能要求

### 9.1 隐私与安全

- 默认只使用本地数据库
- 不保存招聘平台密码、Cookie、短信验证码、Token
- 用户个人信息不写入日志
- 本地单用户测试界面默认不打码手机号、邮箱等个人信息
- 个人信息不得默认上传第三方服务
- 生成内容发送前必须可预览
- 支持导出和删除本地数据
- 面试录音默认只保存在本地路径，不上传第三方服务
- 面试录音转写文本和分析结果可由用户删除

### 9.2 可维护性

- 模块边界清晰
- 平台适配器可插拔
- 分析逻辑和 UI 解耦
- 自动化行为有日志
- 关键评分规则可配置

### 9.3 可测试性

- JD 解析应有样例测试
- 匹配评分应有固定案例测试
- 风险识别应有黑名单/灰名单测试
- 面试题生成应可基于固定输入复验

### 9.4 导出

- 不需要导出投递周报。
- 面试复盘需要支持保存。
- 面试复盘后续支持导出 Markdown。
- PDF 导出可以作为增强项，优先级低于 Markdown 导出。
- 面试复盘 Markdown 不需要固定模板。
- 导出内容应根据当次面试信息动态组织，但至少包含岗位信息、面试问题、未答好问题、改进建议和下一步复习计划。

## 10. 暂不做内容

第一版暂不做：

- 绕过验证码
- 平台账号密码托管
- 大规模自动群发
- 自动修改在线简历
- 自动伪造项目经验
- 对接真实付费招聘 API
- 将简历和投递记录上传云端
- CSV/Excel 批量导入 JD
- 自动点击投递或发送消息
- 默认上传面试录音到第三方转写服务
