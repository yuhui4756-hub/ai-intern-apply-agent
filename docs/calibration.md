# 真实页面校准

更新时间：2026-09-27

本文件说明项目如何把真实招聘页面的只读观察转化为可复核工程改进。它不包含公司名称、岗位 JD、会话正文、浏览器标签 ID、Cookie、验证码、简历或截图。原始本地观察、SQLite 数据和截图均不提交到仓库。

## 原则

- 只在用户已登录、明确启动的受控 Edge 页面上读取；不发送消息、不上传简历、不选择文件、不投递或提交表单。
- 平台页面、DOM 文本和视觉模型输出都是不可信证据，只能补充本地字段，不能改变工具白名单、确认闸门或浏览器权限。
- 每次观察按“页面读取结果”“字段诊断”“规则预筛”“人工反馈”分开统计。未被人工标注的样本不能用于宣传准确率。
- `/calibration` 和 `/calibration/export.json` 只读取本地 SQLite 汇总，不调用模型、不访问浏览器、不改写候选或岗位状态。

## 已落实的观察与调整

### 同平台重复标签

真实使用中，受控 Edge 可能同时存在多个同平台搜索标签，甚至 URL 只在查询参数编码上不同。仅按平台名或文本查找会误读旧页面。

调整：手动打开搜索页时保存应用创建的 CDP target ID；后续采集与显式视觉复核优先绑定该 ID，并再次核验平台。URL 查询参数使用解析后的键值对比较，因此 `+` 与 `%20` 的空格编码视为同一查询。标签已经关闭、跳转为非搜索页或平台不符时，操作失败并要求重新打开页面。

### 字段质量与薪资字体

真实搜索卡会将薪资渲染为私有字体，也会把技术词、经验区间或薪资残片混入公司字段。把这些内容猜成公司或薪资会污染后续筛选。

调整：已知技术词、纯经验标签、私有字体薪资片段不再作为公司名；无法可靠识别的薪资保留为“未解析”，不会按低薪处理或伪造数值。质量面板单独展示标题、公司和薪资异常，供人工选择是否继续读取 JD。

### 视觉复核的合并边界

视觉模型适合补充动态卡片的可见字段，但不能取代链接、DOM 身份和筛选流程。

调整：显式“采集并视觉复核”只截取当前受控搜索页的内存截图，不写入磁盘。视觉字段只有在能与一个 DOM 候选唯一对应时才合并；无法唯一对应的结果保持待人工复核。截图使用后即丢弃，审计只记录是否发生视觉复核与合并数量。

### JD 风险信号的依据

模型会把外部公司印象或薪资市场判断误写成“风险/谨慎”。这类推断不能影响本地分级。

调整：结构化抽取 prompt 明确要求风险与谨慎项必须是 JD 中可见的简短证据；分析和本地重新评分都会丢弃不直接出现在 JD 文本中的模型信号。公司公开风险查询仍是用户明确触发、单独保存来源的流程。

### 零结果页面

已观察到已登录搜索页返回零候选。该结果可能来自真实供给、搜索条件、平台筛选或动态页面结构，不能被解释为平台整体无岗位、抓取准确率或登录失败。

调整：页面读取结果单独记录为“完成 / 无结果 / 失败”，并在质量面板按平台和关键词显示。后续需要结合更多不同条件的人工标注和详情读取，才能判断是产品问题还是页面差异。

## 本地验证范围

本轮本地校准验证了：同平台重复标签的 target 绑定、等价查询编码、受控详情读取、字段异常识别、唯一视觉字段合并，以及模型风险信号的文本落地检查。所有浏览器动作均为读取或应用自建临时详情页的读取；未执行沟通、简历操作或投递。

相关回归测试位于 `tests/test_job_searcher.py`、`tests/test_visual_page.py`、`tests/test_app_flow.py` 与 `tests/test_calibration_dashboard.py`。建议每次调整平台解析后运行：

```powershell
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\python -m compileall app tests evals
.\.venv\Scripts\python -m evals.run_agent_quality_eval --strict
```

## 不应由本页得出的结论

- 不能把页面读取次数、候选数、字段完整率或离线测试通过率写成平台准确率。
- 不能把零结果页面解释为平台无岗位或招聘方无需求。
- 不能把受限消息能力描述为已验证的自动回复效果。
- 不能把视觉补充描述为可绕过登录、验证码、反爬或人工确认。
