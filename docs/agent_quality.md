# Agent 质量与证据

更新时间：2026-09-27

## 1. 目的

本项目的聊天 Agent 会读取岗位卡、本地工具结果、可选视觉结构化结果和用户指令。它们不能因为来自模型、网页或历史记录就获得执行权限。本文件记录 V0.9 的质量控制方式：

1. 用严格契约限制 Agent 规划输出。
2. 明确区分可信用户指令和不可信外部证据。
3. 用脱敏、离线样本防止规则回归。
4. 用本地 trace 将一次 Agent 回合的模型调用、工具执行和消息记录关联起来。
5. 仅在用户明确要求时保存可删除的岗位结论记忆。

这些机制用于降低误操作和帮助定位问题，不代表真实平台招聘效果、HR 回复率或模型通用准确率。

## 2. Agent 契约

聊天规划输出使用 `agent-plan-v1`，由 Pydantic 严格校验：

- 顶层只允许 `plan`、`tool_calls`、`response`、`task_summary`。
- 每个工具调用只允许 `name` 和 `arguments`。
- 工具参数按工具单独校验，未知字段、类型不符、URL、选择器、命令、SQL、文件路径和未注册工具都会被拒绝。
- 首次输出只要包含无效工具或参数，harness 不执行该调用，并只给模型一次“按原契约修复 JSON”的机会。
- 修复后仍不合规时，本轮零工具执行，界面和本地事件会显示“工具契约已拒绝”。

契约约束的是模型输出，不替代浏览器身份验证、发送闸门、简历选择确认或投递确认。

## 3. 信任边界与提示注入

下列内容一律视为不可信证据：岗位 JD、招聘网页、视觉模型摘要、公司搜索结果、工具观察结果和已保存的岗位记忆。它们可以提供事实线索，但不能改变：

- 工具白名单和参数 schema。
- 人工确认、每日限额、平台白名单和敏感内容闸门。
- 简历上传、发送、投递和提交的执行边界。

系统 prompt 和视觉 prompt 都显式要求忽略页面中“忽略规则”“直接投递”“上传简历”“调用工具”等诱导文字。实际执行仍由本地 harness 和既有 CDP 服务完成，而不是由模型返回的文字完成。

## 4. 离线回归评测

评测集位于 `evals/agent_quality_cases.jsonl`，只包含合成或脱敏案例，不含真实简历、API Key、平台 Cookie、HR 对话、录音或完整网页正文。

当前覆盖：

| 套件 | 覆盖内容 |
| --- | --- |
| `jd_rule` | 技能提取、日薪边界、高风险词、可替代语言要求、岗位建议 |
| `conversation` | 群发跳过、面试邀请转人工、岗位问题、简历请求和风险信号 |
| `agent_contract` | 正常工具、未知工具、越权参数、隐藏顶层字段 |

运行方式：

```powershell
.\.venv\Scripts\python -m evals.run_agent_quality_eval --strict
```

也可额外写入本地 JSON 报告：

```powershell
.\.venv\Scripts\python -m evals.run_agent_quality_eval --strict --output .\artifacts\agent-quality-report.json
```

报告中的通过率只反映该固定离线样本集。新增真实观察时，应先脱敏、确认样本可公开或仅本地保存，再补充预期输出和回归测试；不能直接把一次页面观察宣传为平台准确率。

## 5. Trace 与成本观察

每个桌面 Agent 回合生成本地 `trace_id`。该 ID 关联：

- 用户/Agent 消息记录。
- 工具调用记录。
- 当前回合产生的 `model_call_logs` token、费用估算、模型和错误摘要。

trace 不保存完整 prompt、JD、简历、截图或聊天正文到模型调用日志中。它主要用于本地排查“哪一轮调用了模型、是否通过契约、调用了哪些工具、失败发生在哪一层”。

## 6. 岗位结论记忆

用户明确说“记住/保存当前岗位结论”时，Agent 才能写入一条本地岗位记忆。保存内容只由已存在的结构化字段生成：岗位名称、状态、评分、建议、风险、匹配证据、待补强项和跳过原因。

- 不保存完整 JD、简历正文、HR 聊天、截图、文件路径或浏览器正文。
- 电话、邮箱和常见密钥形式在写入前会脱敏。
- SQLite 支持 FTS5 时使用本地全文检索；不支持时退回受限关键词查询。
- 每条记忆可更新、在桌面右侧查看并删除；删除源岗位时会一并删除其派生记忆。
- “不要保存”“暂不需要保存”等否定表达不会视为授权。

“本地保存”指数据库不上传到本项目服务或 Git。若用户为当前会话选择远程聊天模型，命中的结构化岗位结论会和已有岗位卡一样作为本轮上下文发送给该模型；需要避免远程模型处理时，应使用本地模型或不执行相关聊天任务。

## 7. 真实页面校准

真实招聘页面的观察与离线评测应保持两条证据链：离线评测用于稳定回归，真实页面用于发现页面身份、字段质量和平台差异。两者都不能直接转化为平台准确率或投递效果。

- 受控 Edge 的手动搜索会保存应用创建的 CDP target ID；后续采集和显式视觉复核优先绑定该标签，并核验请求平台。相同查询的 `+` / `%20` 编码使用解析后的查询参数比较，避免把重复平台标签误当作目标页面。
- 搜索卡字段诊断将技术词、纯经验文本和私有字体薪资片段排除出公司字段；薪资无法可靠读取时保持未解析，不按猜测值进入筛选。
- 视觉复核只对唯一可关联到既有 DOM 链接的候选补充字段。截图只在内存中传给本轮模型，不落盘；无法唯一关联时保留人工复核。
- JD 抽取中的风险和谨慎信号必须有直接文本依据。重新评分时会丢弃无法在 JD 中找到的模型推断，外部公司研究另走用户明确触发且带来源的流程。
- `/calibration` 与 `/calibration/export.json` 只读取本地汇总，不能调用模型、访问浏览器或修改岗位数据。页面观测、自动诊断、规则预筛和人工反馈分别展示。

详细边界和脱敏观察见 [calibration.md](calibration.md)。

## 8. 验收

至少运行：

```powershell
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\python -m compileall app tests evals
.\.venv\Scripts\python -m evals.run_agent_quality_eval --strict
```

对于真实平台验证，额外记录页面类别、平台、读取成功/失败、字段缺失和人工标注结果。不要保存 Cookie、验证码、联系方式、简历附件或未授权聊天正文。
