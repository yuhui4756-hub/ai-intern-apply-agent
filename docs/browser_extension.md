# 浏览器扩展采集

更新时间：2026-08-05

本扩展用于在用户正常登录的 Edge/Chrome 中采集当前岗位页、搜索结果页或当前 HR 对话页，并发送到本地简历投递 Agent。

## 功能

- 采集当前岗位：读取当前页 URL、标题、正文可见文本和链接，发送到本地应用，创建岗位并分析；默认不预生成打招呼话术。
- 采集搜索结果：读取当前页 URL、标题、正文可见文本、链接和候选卡片可见文本，发送到本地应用，创建搜索记录和候选岗位列表。
- 采集当前对话：读取当前 HR 对话页已加载的可见文本，生成待确认草稿或转人工提示，并写入一次单会话巡检记录。

当前不做：

- 自动回复 HR。
- 自动投递。
- 上传或发送简历。
- 读取 Cookie、密码、验证码、请求头、本地存储、隐藏字段或截图。

## 安装

1. 确认本地应用已启动：

   ```powershell
   .\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
   ```

2. 打开 Edge 扩展管理页：

   ```text
   edge://extensions
   ```

3. 打开“开发人员模式”。
4. 选择“加载解压缩的扩展”。
5. 选择本仓库中的 `browser_extension/` 目录。

Chrome 也可以使用同样方式加载：

```text
chrome://extensions
```

## 使用

### 采集当前岗位

1. 在招聘平台打开岗位详情页。
2. 点击浏览器工具栏里的“简历投递 Agent 采集器”。
3. 点击“采集当前岗位”。
4. 扩展会返回“打开本地结果”，点击后进入岗位详情页。

### 采集搜索结果

1. 在招聘平台打开搜索结果或岗位列表页。
2. 点击浏览器工具栏里的“简历投递 Agent 采集器”。
3. 点击“采集搜索结果”。
4. 扩展会返回“打开本地结果”，点击后进入候选岗位列表。
5. 在候选列表点击“导入分析”时，应用会优先抓取岗位详情页；如果详情页被登录、验证码或动态页面挡住，会先用搜索结果页摘要创建一个待补充岗位。

如果摘要岗位不够完整，推荐流程是：点击候选岗位标题打开招聘平台详情页，在已登录页面中再点扩展的“采集当前岗位”。这样采集的是当前详情页可见 JD，比本地后端直接抓取公开链接更稳定。

### 采集当前对话

1. 在招聘平台打开某一个 HR 对话页。
2. 点击浏览器工具栏里的“简历投递 Agent 采集器”。
3. 点击“采集当前对话”。
4. 扩展会返回“打开本地结果”，点击后进入“沟通草稿”页。

对话采集只读取当前页面已经加载的可见文本，不批量读取全部会话。识别到面试邀请时，只会标记岗位为“面试邀请”，不会自动回复面试时间。

“沟通草稿”页会保留当前页面原始可见文本、清洗后文本和被过滤的页面按钮/系统噪声行。若出现误判，可以在最近对话采集里标记“误判”、选择期望分类并写备注，用于后续校准。

如果设置页的沟通模式为“关闭”，点击“采集当前对话”不会保存、分析或生成草稿。自主询问模式当前也只生成待确认候选草稿，不会自动发送。

如果全局自动化处于暂停状态，采集当前对话会记录为“已暂停”并跳过分析。如果同一岗位或同一会话没有新增可见文本，会记录为“无新内容”，不调用模型，不生成重复草稿。

设置页的定时巡检目前只是调度壳：可以保存启停、间隔和 cooldown，也可以手动 tick，但还不会自动读取浏览器页面。真实定时巡检需要后续接入浏览器巡检执行器。

## 巡检 observation 接口

本地应用已提供巡检执行器接口：

```text
POST http://127.0.0.1:8000/api/message-patrol/observations
```

它用于后续扩展监听器或 Playwright 把当前对话页“已加载的可见文本”上报给本地 Agent。

默认请求应使用 `dry_run=true`：

```json
{
  "executor": "browser_extension",
  "dry_run": true,
  "observations": [
    {
      "url": "https://www.zhipin.com/job_detail/example.html",
      "title": "某公司 HR 对话",
      "platform": "Boss 直聘",
      "text": "当前页面已加载的可见对话文本"
    }
  ]
}
```

`dry_run=true` 只做本地清洗、岗位匹配、重复差分和巡检统计，不保存聊天全文，不生成草稿，不调用模型。只有显式传 `dry_run=false`，才会复用现有“采集当前对话”流程生成待确认草稿。

当前仍未实现真实自动巡检执行器；这个接口只是执行器和本地 Agent 之间的安全契约。

## 常见问题

### 提示无法连接本地应用

确认本地服务正在运行，并且浏览器可以打开：

```text
http://127.0.0.1:8000
```

### 没有识别到候选岗位

可能原因：

- 当前页面不是搜索结果页。
- 页面上的岗位链接尚未加载出来。
- 招聘平台改了链接结构。

可以先滚动页面，确保岗位列表已经出现在页面里，再重新采集。扩展只会采集当前页已经加载出来的可见文本，不会自动翻页或抓取未打开的详情页。

### 薪资显示为方块

部分招聘平台会用特殊字体或反爬方式隐藏薪资数字，浏览器可见但 DOM 文本里只剩 `□□□-□□□元/天`。这种情况下扩展会标记为“薪资数字未能从页面文本读取”，后续可考虑加 OCR/截图识别作为补充，但不建议把 OCR 作为主采集路线。

### 为什么不是直接读取普通 Edge 当前页

普通 Edge 页面不能被本地后端稳定读取。扩展运行在用户当前登录的浏览器里，能避免重复登录，同时不需要读取 Cookie 或平台密码。
