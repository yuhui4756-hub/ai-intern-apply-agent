# 项目状态

更新时间：2026-08-17

## 当前结论

项目已经完成 V0.1 本地求职驾驶舱的大部分核心能力、V0.2 浏览器扩展采集 MVP、V0.3 对话采集与草稿模式 MVP，并已推进 V0.4 沟通模式控制、受控 Edge 巡检与受限自主询问，以及 V0.8 的受控岗位发现。自动投递、简历上传和表单提交尚未开始；当前仅支持受确认的投递附言文本预填。

自动化路线和安全边界已沉淀到 [agent_automation_plan.md](agent_automation_plan.md)。后续实现应优先按该文档推进，避免在实验性 Playwright 搜索采集和长期浏览器扩展路线之间来回摇摆。

现在推荐的主流程是：

1. 在“岗位搜索”点击“开始岗位发现”，在受控 Edge 中轮换搜索 3 个页面，并最多读取、评分 6 个 JD。
2. 使用浏览器扩展采集当前岗位页、搜索结果页或当前 HR 对话页，或手动复制 JD / 岗位链接到应用，作为补充和校准入口。
3. 应用做 JD 抽取、匹配评分、风险判断和话术生成。
4. 对 HR 对话按当前沟通模式生成待确认草稿、转人工提示，或在明确开启的自主询问模式下执行受限的岗位相关询问。
5. 用户人工确认后投递或处理需要人工决策的沟通。

受控 Edge 岗位发现是当前主搜索入口；招聘平台页面仍会变化，浏览器扩展、岗位链接和 JD 粘贴保留为回退及校准工具。

## 已完成

- GitHub 仓库、MIT License、README、需求文档。
- 本地 FastAPI + Jinja2 网页界面。
- 本地 SQLite 数据库存储。
- 候选人画像与四份简历版本管理。
- 项目事实库：支持可视化编辑，并手动刷新具体 GitHub 仓库 README、语言和最近提交；刷新结果只作为事实证据，不自动夸大为技能。
- JD 粘贴分析。
- 多段 JD 批量导入。
- 岗位链接导入，支持 HTTP 抓取和浏览器渲染抓取。
- 岗位匹配评分：高匹配、 中匹配、低匹配。
- 投递建议：必投、可冲、跳过。
- 风险关键词和黑名单公司。
- 公司公开信息搜索与来源链接展示。
- 投递话术和邮件草稿生成。
- 一键复制话术。
- 岗位状态管理和批量状态更新。
- 搜索候选岗位记录、失败记录和候选导入。
- 受控 Edge 岗位发现：按候选人画像轮换 Boss 直聘、猎聘、实习僧搜索；点击前显示本轮关键词和城市，单次最多 3 个搜索页、18 个候选/页和 6 个 JD 读取评分。候选按链接去重，并先按平台详情链接、标题可读性和 AI 研发相关度过滤及排序；导航链接不会入库，文字损坏或未命中的候选保留为“初筛待确认”。
- 受控 Edge CDP：岗位搜索、对话巡检、投递页面演练、消息探测、受确认草稿填入和受限发送均通过原生 CDP WebSocket 执行，不再通过短生命周期 Playwright CDP 连接接管页面；真实 Boss 搜索页读取、临时聊天页填入和一次发送验证后，目标页始终保持打开。JD 详情只会创建并关闭应用自身的临时目标页。
- 聊天页结构校准：可在没有岗位草稿的情况下，对受控 Edge 内已打开的招聘平台页面做只读结构检查，记录平台、聊天页线索、面板/输入框/发送按钮数量和敏感提示数量；不保存正文、标题或链接，不填入、不发送，也不自动改写选择器。当前 PC 消息自动化仅支持 Boss 直聘、猎聘；实习僧 PC 端只能查看消息，不进入巡检、草稿填入或自动回复。实习僧、智联招聘和前程无忧仍可用于岗位发现、JD 分析和投递准备。
- 受控 Edge 短暂断连恢复：搜索页与 JD 详情读取识别到已知 CDP 临时断连后最多自动重试一次；成功重试会保存在搜索记录、岗位事件和岗位发现审计信息中，不会重试登录、验证码、消息或投递动作。
- 受控 Edge 就绪状态：岗位搜索页会只读显示专用浏览器连接状态、页面数量和已识别招聘平台，明确区分普通 Edge 与受控窗口；不读取页面正文、Cookie、标题或 URL。
- 候选校准反馈：在搜索候选页可记录正确、误判或待观察，以及期望分流和备注；反馈保存为本地校准样本和审计日志，当前不会自动重写筛选规则或执行平台操作。
- 候选校准报告：汇总本地候选标注覆盖率、平台准确率、误判期望分流、详情待补充数量和最近误判样本；报告只读，不调用模型或自动改写筛选规则。
- JD 语义评分校准：显式“至少一种/之一”的技术栈作为可替代要求处理，Claude Code、Codex、Cursor 等 AI 编程工具不计入能力缺口；评分优先基于简历正文，正文为空时只使用候选人画像中明确填写的技能作为证据。明确高门槛能力且覆盖率较低时会保守下调技术分。岗位详情可按当前本地规则重新评分，不调用模型、不重新抓取 JD，也不改变岗位流程状态。
- 岗位深度匹配复核：用户可在岗位详情手动调用 `job_match` 路由模型，基于 JD、候选人明确事实和本地规则结果生成补充证据、缺口与沟通前问题；结果独立保存，不会修改本地评分、建议、风险、状态或投递准备。
- 岗位发现筛选：候选人画像可维护目标城市优先级、最低/目标日薪、到岗天数、实习周期和远程偏好；岗位搜索页可临时覆盖本次关键词、城市与筛选条件，并选择同步保存。实际生效条件会记入发现审计日志。搜索摘要或 JD 明确写出的日薪低于底线时会跳过后续 JD 读取或归档，月薪和未披露薪资不会被误判为低日薪。
- 岗位发现强制无外发：不会自动发送 HR 消息、创建投递准备、上传简历或点击投递；详情页不可读取时保留“详情待补充”供用户处理。
- 浏览器扩展采集 MVP：在已登录的 Edge/Chrome 当前页采集岗位详情或搜索结果。
- 本地扩展采集 API：岗位详情直接创建岗位并分析，搜索结果创建候选岗位列表。
- 浏览器扩展对话采集：当前 HR 对话页可见文本采集、分类和草稿队列。
- 面试邀请识别：识别到面试/笔试/约时间后标记岗位为“面试邀请”，不自动回复时间。
- 沟通草稿队列：草稿可编辑、复制、标记已发送、驳回或需要我处理。
- 受控 Edge 草稿填入：仅允许单条“待确认”且通过发送闸门的岗位沟通草稿，在用户输入确认短语并通过平台、岗位、聊天页和敏感文本检查后填入当前 Edge 输入框；不点击发送、不上传简历、不提交表单。
- 对话采集校准入口：保存原始可见文本、清洗后文本、过滤行和用户反馈，用于修正真实平台误判。
- 全局沟通模式开关：关闭、草稿模式、自主询问模式；自主询问仅在用户显式启动、岗位低风险、页面身份和发送控件唯一、内容不含敏感信息时发送岗位相关询问，并受每日 5 条、单平台每日 3 条和轮次上限约束。
- 行为审计日志：记录对话采集、草稿处理、分类反馈和沟通设置变更，可在“沟通草稿”页回看。
- 自动化暂停 / 恢复：设置页和沟通草稿页可暂停对话自动化，暂停后对话采集、定时巡检和后续自动动作会跳过；用户手动点击的 Edge dry-run 巡检仍可执行只读差分。
- 对话差分跳过：同一岗位或同一会话的清洗后文本没有变化时跳过分类和草稿生成，避免重复 token 消耗。
- 单会话巡检记录：每次扩展采集当前对话都会写入巡检批次，记录检查数、新内容数、跳过数和错误数。
- 定时巡检执行器：可配置启停、间隔和手动 tick cooldown；启用后会尝试读取受控 Edge 中已打开的招聘平台聊天页可见文本，先做本地差分；草稿模式只生成记录，自主询问模式才会交给受限发送闸门。
- 巡检 observation 接口：外部浏览器执行器可上报当前对话可见文本；默认 dry-run 只做清洗、岗位匹配、重复差分和巡检统计，不保存聊天全文、不生成草稿、不调用模型。
- Edge 巡检窗口入口：可从“沟通草稿”或“设置”页打开受控 Edge 窗口，并手动触发“巡检当前 Edge 聊天页”。
- 待面试自动准备：岗位状态改为“待面试”或“面试准备中”时，本地生成面试准备记录，并在岗位详情页展示入口；重复保存不会重复创建。
- 智能面试强化：面试准备详情支持用户手动调用 `interview_prep` 模型路由，以 JD、候选人明确填写的资料与待练习薄弱点增强计划、题库和 Markdown；未配置或失败时不会覆盖原材料。
- 面试准备、面试复盘保存和 Markdown / PDF 导出。
- 面试薄弱点库：在面试准备详情里记录没答好的问题、当时回答、卡住点和补强计划；后续同岗位准备会带入仍为“待练习”的薄弱点。
- 本地模拟面试：按题逐题作答，题目优先取待练习薄弱点，再补充面试题库；“没答好”会创建或更新薄弱点，“答得不错”会标记对应薄弱点为“已补强”。
- 本地面试录音转写：支持上传 mp3、m4a、wav、mp4、aac、flac、ogg 文件，使用 faster-whisper 的 CPU `int8` 路线在本机转写；模型文件保存在 `private/whisper_models/`，录音和转写内容保存在 `private/`，不上传第三方服务。完成转写后自动把文本并入面试准备并刷新题库；删除会同时移除本地文件、转写记录和对应准备文本。
- 投递准备队列：可批量整理“必投/可投递”且“低/低风险”的待处理岗位，保存可解释的投递理由和简历版本建议；用户确认后只把本地岗位状态改为“待投递”。“投递准备”可从顶部导航和沟通草稿页顶部进入。
- 投递页面只读演练：已确认的待投递岗位可在受控 Edge 打开来源页，并检查页面身份、投递按钮和简历控件；不填写、不上传、不点击。
- 受确认投递附言预填：用户可在投递准备中保存附言，在输入确认短语后仅向受控 Edge 中身份唯一匹配的附言/自我介绍文本框填入内容；不上传简历、不点击投递或提交表单，页面含验证码、费用或身份信息提示时停止。
- OpenAI-compatible 模型配置档。
- 任务级模型路由。
- Token 消耗与费用估算统计。
- 设置页直接保存 API Key 到本地 `.env`，页面只显示打码状态。
- 工程证据笔记：记录真实工程问题、设计取舍、验证证据和未验证边界，供后续简历与面试材料使用。

## 部分完成

- Word/PDF 简历读取：支持 DOCX、PDF、TXT、Markdown 的本地文本提取，但没有做完整简历结构化编辑体验。
- 公司风险搜索：岗位分析仅保留 JD 风险词和黑名单判断；用户有投递意向后可在岗位详情手动查询并保存公开搜索摘要，仍不是完整的公司尽调系统。
- 聊天控制层：支持受限的岗位发现、本地岗位短名单、隐私保护的简历就绪检查、用户明确触发的受控 Edge 未读标记扫描、岗位解释、状态感知的下一步建议、两岗位本地比较、当前岗位工作记忆、深度匹配复核、带来源状态校验的本地状态变更确认、待面试后的本地面试准备、投递准备、沟通准备与用户明确触发的公开公司风险查询；不开放 LLM 自由工具调用、浏览器直连或未确认的外发动作。
- 浏览器岗位搜索采集：已能打开搜索页和保存失败原因，但对招聘平台登录、动态页面、反爬和浏览器会话依赖较强。
- 自动分档：已有基于评分的默认分档，但仍需要更多真实 JD 样例校准。
- HR 对话草稿：已有规则分类、可选 LLM 增强入口和误判反馈入口，但仍需要继续积累真实平台样本校准分类边界。
- 自主询问模式：已有受限自动发送、轮次约束、候选草稿元数据、基础审计日志、单会话巡检记录、巡检 observation 接口，以及显式确认后的单条浏览器草稿填入；不接入简历上传或表单提交。

## 浏览器采集路线建议

短期继续保留两条稳定入口：

- 粘贴 JD 文本。
- 粘贴岗位链接导入。

中期新增一个 Edge/Chrome 扩展：

- 扩展运行在用户正常登录的浏览器里，不需要重复登录招聘平台。
- 扩展按钮或侧边栏读取当前页标题、URL、正文和岗位链接。
- 扩展把采集结果发给本地应用。
- 本地应用只保存岗位相关文本和链接，不保存平台 Cookie、密码或验证码。

长期自动投递建议使用独立的受控浏览器 profile：

- 用户只需要为这个 profile 登录一次各个平台。
- 自动化只在这个 profile 内执行。
- 高风险动作继续保留用户确认。
- 不把登录 Cookie 写入数据库或 GitHub。

## 下一步建议

继续补充 Boss、猎聘等真实页面的候选与 JD 样本，校准筛选命中质量；优先实现受限的 Agent 对话控制层，以及 Boss、猎聘消息列表中的未读会话只读发现。群发式“求投递”消息作为无需回复的负样本校准，不能当作真实有效沟通。实习僧只保留岗位发现、JD 分析和移动端人工回复。实际发送继续受既有启动、限额、身份、唯一页面和敏感内容闸门约束。

建议下一阶段拆成三步：

1. 在 Edge 开发者模式重新加载 `browser_extension/`。
2. 分别用 Boss 直聘、猎聘等真实页面测试“采集当前岗位”“采集搜索结果”“采集当前对话”；实习僧仅测试岗位采集与 JD 分析。
3. 在“沟通草稿”的最近对话采集中标记正确、误判或待观察，并记录期望分类。
4. 从“求职流程”或“岗位搜索”点击“开始岗位发现”，在该受控 Edge 中完成各平台登录，再观察搜索候选、JD 读取和“详情待补充”的比例。
5. 从“沟通草稿”页打开受控 Edge 巡检窗口，并用“巡检当前 Edge 聊天页”验证新内容、无新内容和文本过短的判定。
6. 根据真实页面结果优化候选链接抽取、JD 详情读取、对话文本清洗、聊天页识别和 HR 回复分类。

高级搜索中的独立浏览器“打开 Edge 搜索页 / 自动采集”保留为排查工具；后续主路线是共用登录状态的受控 Edge 岗位发现。
