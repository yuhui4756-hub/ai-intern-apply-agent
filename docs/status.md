# 项目状态

更新时间：2026-08-08

## 当前结论

项目已经完成 V0.1 本地求职驾驶舱的大部分核心能力、V0.2 浏览器扩展采集 MVP、V0.3 对话采集与草稿模式 MVP，并已推进 V0.4 沟通模式控制、受控 Edge dry-run 巡检，以及 V0.7 的待面试自动准备、面试薄弱点库、模拟面试练习、GitHub 项目事实刷新和本地面试录音转写。自动发送、自动页面填写和自动投递尚未开始。

自动化路线和安全边界已沉淀到 [agent_automation_plan.md](agent_automation_plan.md)。后续实现应优先按该文档推进，避免在实验性 Playwright 搜索采集和长期浏览器扩展路线之间来回摇摆。

现在最可靠的主流程是：

1. 使用浏览器扩展采集当前岗位页、搜索结果页或当前 HR 对话页。
2. 或手动复制 JD / 岗位链接到应用。
3. 应用做 JD 抽取、匹配评分、风险判断和话术生成。
4. 对 HR 对话生成待确认草稿或转人工提示。
5. 用户人工确认后投递或沟通。

Playwright 搜索采集目前属于实验能力，不应当作为唯一主流程。

## 已完成

- GitHub 仓库、MIT License、README、需求文档。
- 本地 FastAPI + Jinja2 网页界面。
- 本地 SQLite 数据库存储。
- 候选人画像与四份简历版本管理。
- 项目事实库：支持可视化编辑，并手动刷新具体 GitHub 仓库 README、语言和最近提交；刷新结果只作为事实证据，不自动夸大为技能。
- JD 粘贴分析。
- 多段 JD 批量导入。
- 岗位链接导入，支持 HTTP 抓取和浏览器渲染抓取。
- 岗位匹配评分：高匹配、 中匹配、低匹配。
- 投递建议：必投、可冲、跳过。
- 风险关键词和黑名单公司。
- 公司公开信息搜索与来源链接展示。
- 投递话术和邮件草稿生成。
- 一键复制话术。
- 岗位状态管理和批量状态更新。
- 搜索候选岗位记录、失败记录和候选导入。
- 浏览器扩展采集 MVP：在已登录的 Edge/Chrome 当前页采集岗位详情或搜索结果。
- 本地扩展采集 API：岗位详情直接创建岗位并分析，搜索结果创建候选岗位列表。
- 浏览器扩展对话采集：当前 HR 对话页可见文本采集、分类和草稿队列。
- 面试邀请识别：识别到面试/笔试/约时间后标记岗位为“面试邀请”，不自动回复时间。
- 沟通草稿队列：草稿可编辑、复制、标记已发送、驳回或需要我处理。
- 受控 Edge 草稿填入：仅允许单条“待确认”且通过发送闸门的岗位沟通草稿，在用户输入确认短语并通过平台、岗位、聊天页和敏感文本检查后填入当前 Edge 输入框；不点击发送、不上传简历、不提交表单。
- 对话采集校准入口：保存原始可见文本、清洗后文本、过滤行和用户反馈，用于修正真实平台误判。
- 全局沟通模式开关：关闭、草稿模式、自主询问模式；自主询问先只生成待确认候选草稿并记录轮次 / 上限。
- 行为审计日志：记录对话采集、草稿处理、分类反馈和沟通设置变更，可在“沟通草稿”页回看。
- 自动化暂停 / 恢复：设置页和沟通草稿页可暂停对话自动化，暂停后对话采集、定时巡检和后续自动动作会跳过；用户手动点击的 Edge dry-run 巡检仍可执行只读差分。
- 对话差分跳过：同一岗位或同一会话的清洗后文本没有变化时跳过分类和草稿生成，避免重复 token 消耗。
- 单会话巡检记录：每次扩展采集当前对话都会写入巡检批次，记录检查数、新内容数、跳过数和错误数。
- 定时巡检 dry-run 执行器：可配置启停、间隔和手动 tick cooldown；启用后会尝试读取受控 Edge 中已打开的招聘平台聊天页可见文本，只做本地差分，不调用模型，不保存聊天全文，只保存哈希指纹。
- 巡检 observation 接口：外部浏览器执行器可上报当前对话可见文本；默认 dry-run 只做清洗、岗位匹配、重复差分和巡检统计，不保存聊天全文、不生成草稿、不调用模型。
- Edge 巡检窗口入口：可从“沟通草稿”或“设置”页打开受控 Edge 窗口，并手动触发“巡检当前 Edge 聊天页”。
- 待面试自动准备：岗位状态改为“待面试”或“面试准备中”时，本地生成面试准备记录，并在岗位详情页展示入口；重复保存不会重复创建。
- 面试准备、面试复盘保存和 Markdown 导出。
- 面试薄弱点库：在面试准备详情里记录没答好的问题、当时回答、卡住点和补强计划；后续同岗位准备会带入仍为“待练习”的薄弱点。
- 本地模拟面试：按题逐题作答，题目优先取待练习薄弱点，再补充面试题库；“没答好”会创建或更新薄弱点，“答得不错”会标记对应薄弱点为“已补强”。
- 本地面试录音转写：支持上传 mp3、m4a、wav、mp4、aac、flac、ogg 文件，使用 faster-whisper 的 CPU `int8` 路线在本机转写；模型文件保存在 `private/whisper_models/`，录音和转写内容保存在 `private/`，不上传第三方服务。完成转写后自动把文本并入面试准备并刷新题库；删除会同时移除本地文件、转写记录和对应准备文本。
- 投递准备队列：可批量整理“必投且低风险”的待处理岗位，保存可解释的投递理由和简历版本建议；用户确认后只把本地岗位状态改为“待投递”。
- 投递页面只读演练：已确认的待投递岗位可在受控 Edge 打开来源页，并检查页面身份、投递按钮和简历控件；不填写、不上传、不点击。
- OpenAI-compatible 模型配置档。
- 任务级模型路由。
- Token 消耗与费用估算统计。
- 设置页直接保存 API Key 到本地 `.env`，页面只显示打码状态。

## 部分完成

- Word/PDF 简历读取：已有基础文件路径和文本读取能力，但没有做完整简历结构化编辑体验。
- 公司风险搜索：已有公开搜索摘要，但还不是完整的公司尽调系统。
- 浏览器岗位搜索采集：已能打开搜索页和保存失败原因，但对招聘平台登录、动态页面、反爬和浏览器会话依赖较强。
- 自动分档：已有基于评分的默认分档，但仍需要更多真实 JD 样例校准。
- HR 对话草稿：已有规则分类、可选 LLM 增强入口和误判反馈入口，但仍需要继续积累真实平台样本校准分类边界。
- 自主询问模式：已有设置入口、轮次约束、候选草稿元数据、基础审计日志、单会话巡检记录、定时 dry-run 巡检、巡检 observation 接口，以及显式确认后的单条浏览器草稿填入；暂未接入自动发送、简历上传或表单提交。

## 浏览器采集路线建议

短期继续保留两条稳定入口：

- 粘贴 JD 文本。
- 粘贴岗位链接导入。

中期新增一个 Edge/Chrome 扩展：

- 扩展运行在用户正常登录的浏览器里，不需要重复登录招聘平台。
- 扩展按钮或侧边栏读取当前页标题、URL、正文和岗位链接。
- 扩展把采集结果发给本地应用。
- 本地应用只保存岗位相关文本和链接，不保存平台 Cookie、密码或验证码。

长期自动投递建议使用独立的受控浏览器 profile：

- 用户只需要为这个 profile 登录一次各个平台。
- 自动化只在这个 profile 内执行。
- 高风险动作继续保留用户确认。
- 不把登录 Cookie 写入数据库或 GitHub。

## 下一步建议

优先在真实招聘平台页面验证 V0.3 Edge/Chrome 扩展对话采集、草稿模式和 V0.4 Edge dry-run 巡检。这比直接做自动发送更稳，也更符合当前安全边界。

建议下一阶段拆成三步：

1. 在 Edge 开发者模式重新加载 `browser_extension/`。
2. 分别用 Boss 直聘、实习僧等真实页面测试“采集当前岗位”“采集搜索结果”“采集当前对话”。
3. 在“沟通草稿”的最近对话采集中标记正确、误判或待观察，并记录期望分类。
4. 从“沟通草稿”页打开 Edge 巡检窗口，在该窗口登录招聘平台并打开 HR 对话页。
5. 用“巡检当前 Edge 聊天页”验证 dry-run 是否能正确区分新内容、无新内容和文本过短。
6. 根据真实页面结果优化候选链接抽取、对话文本清洗、聊天页识别和 HR 回复分类。

当前 Playwright 的“打开 Edge 搜索页 / 自动采集”保留为实验能力，不作为后续主路线。
