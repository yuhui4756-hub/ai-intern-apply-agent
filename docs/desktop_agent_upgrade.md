# 求职agent 桌面与对话式 Harness 升级规格

更新时间：2026-08-22

## 1. 目标

将现有 FastAPI + SQLite + 受控 Edge 求职系统封装为 Windows 桌面应用“求职agent”。桌面端的首屏是连续多轮聊天，而不是驾驶舱首页；岗位、简历、投递准备、沟通、面试、设置和审计继续存在，但收纳为岗位画布、右侧上下文面板和可展开的备用工具入口。

本次升级的目标不是把模型变成无约束浏览器脚本，而是实现：

1. 用户用自然语言下达任务，例如“根据我的简历找杭州 AI 应用开发实习，并优先处理有 5 天/周的岗位”。
2. 主 Agent 模型根据本地上下文和有限工具清单规划下一步、调用工具、读取工具结果并给出可读结论。
3. 受控 harness 校验每一次工具调用，执行浏览器读取、视觉复核、本地状态写入和已授权沟通。
4. 桌面端展示计划摘要、工具调用、关键观察、截图结构化结果和确认请求，不展示或持久化模型原始思维链。
5. 页面填写、简历选择、上传和最终投递/提交不因模型规划而自动执行。

## 2. 已确认产品决策

- 平台：Windows Electron 桌面应用，打包后可创建桌面快捷方式；Python FastAPI 服务作为本地 sidecar。
- 主界面：左侧任务会话与画布切换，中间连续聊天，右侧可收起的当前上下文/工具结果面板。
- 岗位画布：一张岗位一个固定小卡，显示公司、岗位、匹配分、建议、状态、薪资和最新摘要；点击卡片只改变中间/右侧上下文，不替换左侧任务导航。
- 模型：输入栏下方提供本轮模型选择器，默认使用已配置的 `GPT-5.6 Terra` 档案；可从已添加模型档案中临时切换。
- 自动沟通：输入栏下方提供“自动沟通”开关。开启后，已通过匹配、平台、轮次、页面身份、敏感文本和每日限额闸门的岗位相关沟通可自动发送；关闭时只生成草稿/请求确认。
- 主动首聊：自动沟通开启时允许作为受限工作流的一部分，但必须先定位唯一岗位页与唯一聊天入口，并仍受每日上限、平台白名单和风险闸门约束。无法唯一定位时转为草稿或人工处理。
- 受控浏览器：继续使用独立 Edge profile 和 CDP，不能嵌入招聘平台登录态到 Electron。
- 记忆：每个任务保留本轮上下文；每轮结束可自动生成一条可编辑任务摘要。长期偏好只保存用户显式内容，候选人事实仍由画像和简历版本提供。
- 名称：`求职agent`。

## 3. 分层架构

```text
Electron desktop shell
  -> chat-first renderer / job canvas / tool drawer
  -> local FastAPI API (127.0.0.1 only)
  -> agent harness (tool schemas, policy checks, audit)
  -> SQLite / existing services / model router
  -> controlled Edge CDP / public research / local files
```

Electron 只负责启动/停止本地 sidecar、窗口生命周期、外部链接和本地 UI。它不持有招聘平台 Cookie、密码、验证码或 API Key。SQLite、`.env`、受控 Edge profile 与截图临时内存仍由 Python 侧管理。

## 4. Agent 工具契约

### 4.1 模型可见内容

每轮 Agent 模型获得：

- 用户当前请求和最近有限轮的任务会话。
- 当前选中岗位的已脱敏/已结构化本地字段。
- 用户明确保存的长期偏好。
- 受限工具名称、JSON 参数 schema、权限等级与返回摘要。
- 受控 Edge 的连接状态，不提供 Cookie、密码、完整页面 HTML 或未授权聊天正文。

模型不得自行输出或执行任意 URL、JavaScript、SQL、命令行、选择器、文件路径或平台提交动作。

### 4.2 工具等级

| 等级 | 示例 | 执行规则 |
| --- | --- | --- |
| 本地只读 | 查看岗位画布、比较岗位、检查简历就绪、查看任务 | 直接执行并审计 |
| 受控读取 | 搜索岗位、读取 JD、页面截图、视觉复核、查看已打开消息页 | 直接执行，限定 Edge profile、页面身份和次数 |
| 本地写入 | 创建任务、保存任务摘要、生成投递/沟通准备、创建状态变更计划 | 直接执行或先创建待确认计划 |
| 已授权外发 | 自动发送岗位相关消息 | 必须自动沟通开关开启，并通过既有平台、风险、轮次、限额、唯一页面/控件、敏感文本闸门 |
| 高影响动作 | 选择简历文件、上传、填写敏感字段、点击投递/提交 | 一律单独人工确认；最终投递/提交永不自动执行 |

### 4.3 多轮工具调用

Agent 可在一次用户请求内进行有限轮次的“模型规划 -> 工具 -> 观察结果 -> 模型总结”。默认最多 8 次工具调用和 3 次模型规划，超限后保存当前进度并要求用户继续。每个步骤写入可读事件：

- 计划：要解决什么和原因。
- 工具调用：工具名、权限等级、参数摘要。
- 观察：候选数量、JD 是否可读、视觉字段、闸门结论或错误摘要。
- 安全结论：是否发生外发、文件选择或提交。

“推理摘要”是由 harness 要求模型给出的简短可审计说明，不是隐藏思维链。

## 5. 自动沟通策略

自动沟通开关开启后，系统允许执行已经存在的自主沟通发送链路，并扩展为“主动首聊候选”的受限任务。两类操作共同遵守：

- 仅 Boss 直聘、猎聘 PC 端进入自动消息能力白名单；实习僧 PC 端只读。
- 岗位必须为高匹配/建议投递、低风险，且已保存可验证 JD。
- 每日默认最多 5 条，单平台默认最多 3 条，每岗位默认最多 2 轮；设置页可调整。
- 未知/群发/无关/敏感/面试安排/简历附件/联系方式/费用相关内容必须停止并转人工。
- 主动首聊需要唯一岗位页、唯一聊天入口、唯一输入框/发送按钮；无法满足时只保存草稿。
- 关闭自动沟通时，模型可以生成草稿和建议，但不能点击发送。

自动沟通不是“自动投递”：简历选择、上传、最终投递/提交继续独立确认。

## 6. 薪资视觉补全

招聘站点可能将薪资绘制为私有字体，DOM 文本会显示乱码。为避免一个薪资字段使整条候选被拒绝：

1. 岗位标题或核心上下文不可读时，保留为人工复核，不自动读 JD。
2. 标题/公司/方向可读但薪资为空、乱码或无法解析时，标记为 `salary_visual_pending`。
3. 对当前受控搜索页做一次按需截图视觉复核，模型只返回已明确可见的薪资文字；截图只在内存中存在。
4. 视觉薪资只合并到来源链接可唯一对应的候选。无法唯一对应或置信度不足时保持“薪资待确认”，不猜测数字，也不做低薪归档。

## 7. 桌面信息架构

### 左侧

- 新任务。
- 最近任务会话。
- 画布切换按钮。
- 小型备用入口：岗位、投递、沟通、面试、简历、设置、审计。

### 中间

- 默认：聊天消息流，任务事件收在每轮回答下的可展开“计划与工具记录”。
- 画布：按状态/建议筛选的岗位卡片网格。卡片点击后打开岗位检查器，不离开当前任务。
- 备用工具：在同一工作区以紧凑视图打开，保留返回聊天的固定按钮。

### 右侧

- 当前任务：状态、模型、自动沟通、受控 Edge 连接情况。
- 当前岗位：评分、风险、下一步、简历建议。
- 页面观察：最新截图的结构化字段、视觉置信度、未确认项；不显示或保存截图本身。

### 输入区

- 多行输入。
- `+`：打开备用手动动作，包括粘贴 JD、导入链接、选择岗位、打开设置。
- 模型选择器：只列出已配置模型档案，临时选择不覆盖全局路由。
- 自动沟通开关：显示当前授权状态和日/平台/轮次余量。
- 发送按钮。

## 8. 数据与迁移

新增表仅保存本地任务记录与结构化事件：

- `agent_sessions`：会话名称、当前模型档案、自动沟通偏好、任务摘要、时间。
- `agent_messages`：角色、文本、结构化事件、模型档案、会话关联。聊天全文默认本地保存；不会写入 Git。
- `agent_tool_runs`：工具名、权限等级、参数/结果的脱敏摘要、状态、错误、时间。

已有 `control_conversations` 与 `control_plans` 保留兼容；新桌面 Agent 不删除旧 Web 工作流或其审计记录。

## 9. 验收标准

- Electron 应用在 Windows 可启动 FastAPI sidecar、打开主聊天页、退出时停止自身启动的 sidecar。
- 聊天页可选模型、连续多轮、展示工具事件、保存/编辑任务摘要。
- 岗位画布可查看卡片、筛选、点击进入岗位详情，且不覆盖左侧会话栏。
- 模型只能调用 schema 白名单内的工具；越权参数、本地路径、提交动作必须被 harness 拒绝并留审计。
- 自动沟通关闭时，任何发送工具调用均不得点击浏览器发送；开启时仍必须通过现有全部闸门。
- 薪资视觉补全测试覆盖：可唯一合并、无法唯一合并、低置信度不合并、截图不落盘。
- 回归现有搜索、JD、投递准备、沟通、状态机和隐私测试。
- 打包产物不含 `.env`、SQLite 数据库、简历、录音、截图、浏览器 profile 或 API Key。
