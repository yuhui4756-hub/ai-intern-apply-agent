# 简历投递 Agent

面向 AI 应用开发、Agent 开发和 AI 后端实习投递的本地网页 Agent。

当前阶段：V0.8 受控岗位发现与自主沟通。

核心目标：

- 分析岗位 JD 和公司风险。
- 根据简历和偏好判断岗位是否值得投递。
- 生成礼貌、真诚、不夸大的投递话术。
- 管理投递状态和跳过原因。
- 在收到面试邀请后生成准备计划、题库和复盘材料。

需求规格见 [docs/requirements.md](docs/requirements.md)，自动化路线见 [docs/agent_automation_plan.md](docs/agent_automation_plan.md)，浏览器扩展说明见 [docs/browser_extension.md](docs/browser_extension.md)，当前完成度见 [docs/status.md](docs/status.md)。

## Quick Start

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

然后打开 <http://127.0.0.1:8000>。

API Key 可以在设置页直接填写；应用会保存到本地 `.env` 并立即生效，页面只显示打码状态。真实 `.env` 不要提交。

默认浏览器自动化优先使用本机 Microsoft Edge。只有选择 Chromium 时，才需要额外安装一次 Chromium：

```powershell
.\.venv\Scripts\python -m playwright install chromium
```

## Current Includes

- 本地 SQLite 数据库。
- 候选人画像和多份简历版本管理，支持读取 DOCX、PDF、TXT、Markdown 简历文本。
- 项目事实库：可编辑项目事实，并手动刷新具体 GitHub 仓库的 README、语言和最近提交。
- JD 粘贴分析、岗位链接抓取导入、匹配评分、风险判断和一键复制话术。
- 岗位链接支持普通网页抓取和可选 Playwright 浏览器渲染抓取。
- 受控 Edge 岗位发现：从候选人画像轮换搜索 Boss 直聘、猎聘、实习僧，单次最多搜索 3 个页面、读取并评分 6 个 JD；先按候选标题和摘要筛出 AI 研发方向，其他候选保留为“初筛待确认”。
- Edge 浏览器岗位搜索采集：打开招聘平台搜索页，采集候选岗位链接，再逐条导入 JD 分析。
- 浏览器扩展采集 MVP：在已登录的 Edge/Chrome 当前页采集岗位详情或搜索结果。
- 浏览器扩展对话采集：采集当前 HR 对话可见文本，生成待确认草稿或转人工提示。
- 沟通草稿队列：草稿可编辑、复制、标记已发送、驳回或需要我处理。
- 受控 Edge 草稿填入：单条待确认草稿经输入确认和页面身份复核后可填入当前聊天输入框；不点击发送、不上传简历。
- 对话采集校准：保存原始可见文本、清洗后文本和过滤行，可标记误判并记录期望分类。
- 全局沟通模式：关闭、草稿模式、自主询问模式；自主询问会记录轮次和上限，并且只会在用户显式启动工作流、岗位低风险、页面身份唯一且内容不涉及敏感信息时，通过受控 Edge 自动发送。
- 自动化暂停 / 恢复：暂停后跳过对话采集分析和草稿生成，手动 JD 分析与岗位采集仍可继续。
- 对话差分跳过：同一岗位或同一会话没有新增文本时不再重复分析，避免重复草稿和无意义 token 消耗。
- 单会话巡检记录：每次扩展采集当前对话都会写入巡检批次，记录已检查、新内容、跳过和错误计数，不保存聊天全文。
- 定时巡检执行器：可配置启停、间隔和手动 tick cooldown；读取受控 Edge 已打开的招聘平台聊天页并做本地差分。草稿模式只生成记录，自主询问模式才会将新内容交给受限发送闸门。
- 行为审计日志：记录对话采集、草稿处理、分类反馈和沟通设置变更，便于回放 Agent 决策。
- 多段 JD 批量粘贴导入、自动分档和批量状态更新。
- 岗位状态、跳过原因和公司搜索证据记录。
- 面试准备、转写文本复盘和 Markdown / PDF 导出。
- 待面试自动准备：岗位状态改为“待面试”或“面试准备中”时，会本地生成面试准备记录；不自动确认面试时间，不调用模型。
- 面试薄弱点库：记录没答好的问题、卡住点和补强计划，后续同岗位准备会优先带入待练习薄弱点。
- 本地模拟面试：逐题输入回答并记录结果；没答好的题自动回流到薄弱点库，答得不错的薄弱点可标记为已补强。
- 本地面试录音转写：上传录音后使用 CPU 版 faster-whisper 在本机转写，自动补充到面试准备和题库；录音、模型缓存和转写文本均保存在 `private/`，不上传第三方服务。
- 投递准备队列：筛选“必投/可投递”且“低/低风险”的待处理岗位，推荐简历版本并保存投递理由；必须人工确认后才标记为待投递，不会操作招聘平台。
- 投递页面演练：对已确认的待投递岗位，可在受控 Edge 打开岗位页并只读检查页面身份、投递按钮和简历控件；不会填写、上传或点击。
- OpenAI-compatible 模型配置档、任务路由和 token 统计。

## Practical Workflow

建议先按这个顺序使用：

1. 在“设置”页配置模型。搜索采集本身不依赖 LLM，但 JD 抽取、匹配解释、话术和面试准备会用到模型。
2. 在“简历”页确认候选人信息、项目事实和简历版本。可以填写具体 GitHub 仓库链接后刷新项目资料，结果只作为事实库。
3. 进入“岗位搜索”，先核对按钮上方显示的本轮平台、关键词和城市，再点击“开始岗位发现”。应用会使用受控 Edge 的登录状态轮换搜索 3 个页面，并至多读取、评分 6 个 JD。
4. 第一次使用时，在打开的专用 Edge 中登录招聘平台；之后岗位发现、JD 读取和受控沟通共用这个 profile。
5. 在“搜索记录”查看候选、详情待补充和已导入状态；高级搜索与采集保留给排查和手动补充。
6. 在岗位详情页确认“必投 / 可冲 / 跳过”，复制话术或更新投递状态。实际投递和简历上传始终需要人工确认。
7. 需要受控沟通时，在首页点击“启动自主沟通”。应用会打开专用 Edge；完成平台登录并打开 HR 对话页后，定时巡检会处理新消息。只有通过岗位匹配、风险、内容、轮次、页面身份和发送控件唯一性校验的自主询问候选才会发送；其他情况会留在沟通队列或转人工处理。
8. 收到面试邀请时，系统只标记“面试邀请”；你确认时间和形式后，再手动改为“待面试”，系统会创建本地面试准备记录，可从岗位详情或“面试准备”页打开。
9. 在面试准备详情点击“开始模拟面试”，逐题作答。标记“没答好”会回流到待练习薄弱点，下一次准备会优先出现。
10. 从顶部导航或“沟通草稿”页顶部的“投递准备”进入投递准备，点击“生成投递候选”，核对投递理由、简历版本和备注后，再选择“确认待投递”。这只更新本地状态，实际投递仍需要你在平台上执行。
11. 对已确认条目可点击“打开岗位页”和“只读演练”。演练只检查页面是否与岗位匹配、是否找到控件，为后续受控填写做准备。
12. 面试结束后，在对应的“面试准备”详情上传本地录音，选择 `base` 或 `small` 后开始转写。`base` 是 CPU 上的默认推荐，速度和中文识别质量较均衡；首次使用某个模型会下载到 `private/whisper_models/`，后续直接复用。转写完成后会刷新本地准备计划和题库。
13. 不再需要的录音可在同一页面删除。删除会移除本地音频、转写记录以及面试准备中的对应转写段，不会影响手动填写的薄弱点。

当前不会自动点击投递、上传简历、提交表单或绕过验证码。自主发送仅限于用户显式启动的受控沟通工作流，且只允许低风险“必投/可投递”岗位的岗位相关询问：每日最多 5 条、单平台最多 3 条、每个岗位最多按你设置的轮次发送。涉及简历附件、联系方式、面试安排、费用、报价或无法唯一定位聊天页/发送按钮时会停止。未匹配到岗位时也会转为人工处理。全局暂停打开后，对话采集、定时巡检和后续自动动作会跳过；手动 Edge 巡检仍可读取当前聊天页做只读差分。重复采集同一段对话会被差分层跳过，不再调用模型，并在“最近巡检”里记录为无新内容。

岗位发现只会执行搜索、读取 JD、评分、风险分析和本地记录。它不会因为发现到岗位就发送消息、创建投递准备、上传简历或点击投递；详情页暂时无法读取时，候选会标记为“详情待补充”。

本地录音转写需要 `faster-whisper` 和其模型文件。执行 `pip install -r requirements.txt` 后即可使用；`faster-whisper` 会在第一次点击转写时下载所选模型。当前机器优先使用 CPU `int8` 推理，默认选择 `base`；没有 NVIDIA/CUDA 也能运行。安装或下载失败时，页面会保留录音并显示错误，不会上传录音。

受控沟通流程：

1. 在首页或“沟通记录”点击“启动自主沟通”。
2. 在该受控 Edge 窗口登录招聘平台并打开 HR 对话页。
3. 等待定时巡检；需要排查时，可在“沟通记录”的“高级诊断”中手动巡检当前 Edge 页面。
4. 在“最近巡检”查看新内容、无新内容、自动发送、文本过短或浏览器未连接等结果。

岗位搜索采集是浏览器自动化，不是 LLM：Playwright/Edge 负责打开网页、读取链接和页面文本；LLM 只在后续 JD 抽取、匹配解释、话术生成、面试准备等环节参与。

如果“采集当前 Edge 页面”提示无法连接，请先确认使用的是应用打开的专用 Edge 搜索窗口；普通手动打开的 Edge 没有调试端口，应用无法读取当前页面。

模型配置建议：

- `Temperature` 推荐先用 `0.2`。JD 抽取、评分解释这类任务越低越稳定；话术或面试题可以提高到 `0.4-0.6`，但更容易发散。
- `API Key 环境变量名` 可以留空，应用会默认使用 `OPENAI_COMPATIBLE_API_KEY`。这个字段的作用是告诉应用把 Key 存到 `.env` 的哪个变量名下，以及调用模型时从哪里读取。
- 新增模型配置时，如果环境变量名留空，应用会按服务商或配置名称自动建议，例如 DeepSeek -> `DEEPSEEK_API_KEY`，OpenAI -> `OPENAI_API_KEY`。
